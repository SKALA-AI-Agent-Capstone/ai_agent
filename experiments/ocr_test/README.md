# OCR 방식 비교 실험 (ocr_test 브랜치 전용, main에 합치지 않음)

광고 이미지를 내용 구간으로 자른 뒤, 구간마다 글자와 [이미지] 묘사를 두 방식으로 뽑아 나란히 비교한다.
서비스 코드는 건드리지 않고 `capstone_shared.documents`의 `tile_image`(구간 분할)와 `local_ocr`(Tesseract)만 가져다 쓴다.

## 실행

```sh
sh experiments/ocr_test/run.sh      # http://127.0.0.1:8090 에서 이미지를 올리고 '분석'
```

- 호스트에 Tesseract가 없어도 되게 기존 Python 이미지(`beauty-capstone-python:dev`, 한국어 Tesseract 포함)에서 돈다.
- 키는 `../backend/.env`에서 컨테이너 환경으로만 넘긴다. 다른 env 파일은 `ENV_FILE=...`로 지정한다.
- 모델은 env의 `VISION_MODEL`, `TEXT_MODEL`(기본 gpt-5.4-mini)을 쓴다.

## 두 방식

| | 1번: OCR 정리 + 비전 합치기 | 2번: OCR 위치 + 비전 판독 |
| --- | --- | --- |
| OCR | Tesseract가 읽은 줄을 텍스트 모델이 정리(띄어쓰기, 깨진 글자). 이미지는 안 봄 | Tesseract는 글자 위치(줄 상자)만 제공 |
| 비전 | 원본을 직접 읽고, 정리된 OCR 줄을 참고로 받아 합침(중복 제외). OCR 덕분에 찾은 글자는 `source=ocr` | 원본과 번호 상자 그림을 함께 받아 상자마다 글자를 읽고, 상자 밖 글자와 [이미지]를 묘사 |
| 모델 호출 | 구간당 2회(OCR 줄이 없으면 1회) | 구간당 1회 |
| 출력 | 글자 덩어리(따옴표 단위), [이미지] 사실 묘사 | 같음 + 덩어리마다 상자 번호(위치) |

## 2026-10-22 첫 실행 (투집 포어본드 광고 2장)

| 이미지 | 1번 | 2번 |
| --- | --- | --- |
| 06.jpg (848x2412, 2구간) | 호출 3, 입력 3,815 / 출력 683토큰, 8.7초 | 호출 2, 입력 6,147 / 출력 453토큰, 6.4초 |
| 상세페이지 (780x2324, 3구간) | 호출 6, 입력 4,653 / 출력 1,175토큰, 14.5초 | 호출 3, 입력 6,648 / 출력 741토큰, 10.0초 |

구간은 병렬로 처리해 이미지 한 장 전체는 약 6초였다.

### 둘 다 기존 파이프라인보다 나아진 점
- 기존 결과의 대표 오류가 사라졌다.
  - 카드 세 장 제목이 한 줄로 합쳐지던 것("인체 적용 시험 완료 POREBOND™ 2t¢ 모공 특허 듀얼 배합") → 카드별로 분리되어 읽힘
  - "함유"가 "2t¢"로 읽히던 것 → "10,000PPM 함유"로 정확히 읽힘
  - "2주"가 "주"로 빠지던 것 → "2주 안에 개선하는 신개념 모공 케어"로 정확히 읽힘
- 띄어쓰기가 깨진 줄("모공 크 기 와 개 수 가")은 두 방식 모두 바르게 나왔다.

### 차이
- **묶음**
  - 1번은 카드 단위로 자연스럽게 묶었다('01' 'POINT' '인체적용시험 완료' 한 덩어리).
  - 2번은 OCR 상자를 따라 더 잘게 나뉘었다('01' 'POINT'와 '인체적용시험 완료'가 별도). 한국어와 영어 번역 줄도 따로 나뉨.
- **위치**: 2번은 덩어리마다 상자 번호가 붙어 화면 박스를 바로 그릴 수 있다. 1번은 위치 정보가 없다.
- **OCR이 아무것도 못 찾은 구간**: 06.jpg 첫 구간(큰 회색 제목)에서 Tesseract가 0줄을 냈다.
  - 2번은 그때 순수 비전 판독이 된다.
  - 모델이 없는 상자 번호(1~7)를 지어내는 현상이 있어, 코드에서 실제 상자 번호만 남기도록 고쳤다.
- **비용, 속도**: 2번이 호출 수와 시간이 적다. 이미지를 두 장(원본, 상자 그림) 보내서 입력 토큰은 더 많다.

### 둘 다 남은 문제
- **작은 각주 오독**: "*투집 포어본드 일시적 모공..." 각주의 "투집"을 1번은 "튜집", 2번은 "트집"으로 읽었다.
  - 작은 글자는 해당 상자만 확대해 다시 읽는 단계가 필요하다(설계의 '확대 재판독').
- **장식 글꼴 로고**: 첫 구간의 "TUJIB" 로고를 둘 다 "TOJIB"로 읽었다.
- **글자 배치 묘사**: [이미지] 묘사에 "세 줄의 글자가 배치되어 있음"처럼 글자 배치를 쓰는 경우가 있다. 2번이 더 자주 그런다. 프롬프트를 더 좁혀야 한다.
- **1번의 출처 표시**: 1번이 거의 모든 덩어리를 `source=ocr`로 표시한 구간이 있어, 이 표시는 믿기 어렵다.
